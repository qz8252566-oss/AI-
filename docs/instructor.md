# 講師向け資料

講座の準備から当日の対応までをまとめています。初回は「1. 事前準備」を順に進めてください。2章以降は必要なときに引く参照用です。

最終更新：2026-10-19

## 1. 事前準備

### テンプレートリポジトリを用意する

1. このリポジトリを講座用の GitHub アカウント（または Organization）に置きます
2. リポジトリの「Settings」を開き、「General」の一番上にある「Template repository」にチェックを入れます
3. リポジトリの公開範囲を Public にします。受講者が誰でも「Use this template」できるようにするためです。受講者が作るリポジトリのほうは Private にしてもらいます

`.dev/` フォルダ（仕様書と作業指示書）と `scratch/` フォルダは `.gitignore` で除外しているので、テンプレートには含まれません。

### 受講者に事前に伝えること

必要なのは GitHub のアカウントだけです。Codespaces を使うので、受講者のパソコンにソフトを入れる必要はありません。当日アカウントを作ると、メール確認などで時間を取られるので、事前に作ってもらってください。

### 無料プランの受講者を前提にする

受講者は GitHub の無料プランを使う前提で設計しています。

- 受講者が作るリポジトリは Private にしてもらいます（00 の手順）。無料プランでも、Private のリポジトリで Codespaces を使えます。万一キーを `.env` 以外のファイルに書いて push しても、外からは見えません
- GitHub Pages は使いません。このアプリは Node.js のサーバー（`server.js`）が必要で、HTML などのファイルを配るだけの GitHub Pages では動かないためです。無料プランの GitHub Pages が Public リポジトリ限定であることは、この講座には影響しません
- 講座の中では、受講者が commit や push をする場面はありません
- Codespaces の無料枠は、毎月 120 コア時間と 15GB のストレージです。この教材の既定の2コアのマシンなら、月60時間動かせます。90分の講座なら3時間分（コア時間）の消費で収まります
- 無料枠を使い切っても、支払い方法を登録していなければ課金はされず、翌月まで使えなくなるだけです
- 操作しないまま30分たつと、Codespace は自動で止まります。講座の最後に、「Stop codespace」で止めることと、不要になったら削除することを伝えてください（00 の最後に書いてあります）

### APIキーを用意する

さくらのAI Engine のコントロールパネルで、講座専用のアカウントトークンを発行します。

- トークンは `UUID:シークレット` の形で、作成時に一度だけ表示されます。必ず全体を控えてください。一覧画面に出る UUID だけでは認証に失敗します
- 講座が終わったら、そのトークンを削除します

### 利用回数を見積もる

無償プランの月間リクエスト数の上限は、全受講者で共有になります（2025年9月の提供開始時点で、チャット生成は月3,000回）。1回の「つくる」で、AI を最大3回呼びます。

見積もりの目安は次のとおりです。

| 場面 | 1人あたりの回数 |
|---|---|
| 01〜04 でカードを作る | 20〜30回 |
| 05 の NG 体験（1回の「つくる」で3回呼ぶ） | 3〜6回 |
| 06 の発展課題 | 10〜20回 |
| 合計 | 約35〜55回 |

30人なら 1,000〜1,700回ほどです。講座の前に講師がテストした分も同じ上限から引かれます。上限に達すると、全員の画面に「混み合っています」と出る想定です（未検証）。

### 実測値（2026年10月、gpt-oss-120b）

| 項目 | 値 |
|---|---|
| 1回あたりの時間 | 1〜3秒 |
| 1回あたりのトークン数 | 入力 約210 ／ 出力 約170〜600 |
| JSON の指示に従った割合 | 15回中15回 |
| 05 の NG 体験（3回とも NG） | 合計 約13秒 |

## 2. キーの配り方

キーは受講者全員で同じものを使います。配るときは次の点に気をつけてください。

- 講座で使うチャットやスライドにキーを貼った場合は、記録が残るので、講座後に必ずトークンを削除（失効）させます
- 画面共有中に `.env` を開かないようにします。講師がデモをするときも同じです
- 受講者がキーを SNS や公開リポジトリに貼ってしまった場合は、その場でトークンを削除し、新しいトークンを配り直します

## 3. よくあるつまずきと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 【まだ .env ファイルがありません】と出る | `cp .env.example .env` を忘れた。`.env.example` に直接キーを貼った | ターミナルで `cp .env.example .env` を実行し、`.env` にキーを貼り直す |
| 【.env にキーが入っていません】と出る | 貼ったあとに保存していない | `.env` を保存し、Ctrl + C で止めて `npm start` |
| 【注意】キーの形がいつもと違うようです と出る | キーの前後に空白がある、`"` で囲んだ、`:` の後ろを貼り忘れた | `.env` の1行を `SAKURA_AI_TOKEN=キー` の形に直す |
| 「キーが正しくないようです」と画面に出る | キーの写し間違い、トークンを削除済み | キーを貼り直す。直らなければ講師のトークンが有効か確認 |
| config.js を変えても画面が変わらない | ブラウザを再読み込みしていない | F5（Mac は Cmd + R） |
| 【config.js の書き方に間違いがあります】と出る | カンマやかっこの書き間違い | 案内の行番号か、その1つ前の行を直し、Ctrl + C → `npm start`（直して保存しても自動では起動し直さない） |
| 【ポート 3000 がすでに使われています】と出る | 別のターミナルで `npm start` が動いている | 動いているほうのターミナルで Ctrl + C |
| 「サーバーにつながりませんでした」と画面に出る | サーバーが止まっている | ターミナルで `npm start` |
| 「混み合っています」と画面に出る | 短時間に呼びすぎた、または月間上限に達した | 少し待つ。続く場合はコントロールパネルで利用状況を確認 |
| ポートを public にしてしまった | 「ポート」タブで公開範囲を変えた | 3000 の行を右クリック →「ポートの表示範囲」→「Private」。public のままだと、URL を知った他人がそのキーで AI を使えてしまう |

## 4. 講座の前に Codespaces で確かめること

この教材は、手元の Mac（Node.js 22）で動作を確認しています。次の項目は Codespaces 上ではまだ確かめていないので、講座の前に一度通してください。

- 「Create codespace on main」で起動したあと、`npm install` が自動で終わるか
- `npm start` のあと、ブラウザのタブが自動で開くか
- 「ポート」タブで 3000 番の公開範囲が Private になっているか
- `.env` がない状態で `npm start` したとき、日本語の案内のあとに npm の英語のエラーが何行出るか（Node.js 20 では手元と表示が違う可能性があります）
- `.env` にキーを貼って保存したとき、サーバーが自動で起動し直すか（手元の Node.js 22 では起動し直しました。Node.js 20 では起動し直さない可能性があり、その場合も案内どおり Ctrl + C → `npm start` で動きます）

## 5. モデルについての注意

- 既定の `gpt-oss-120b` は、JSON の指示によく従います
- 06 の課題 B で使う `preview/gemma-4-31B-it` は、名前のとおりプレビュー版です。講座の時点で使えるかを事前に確かめてください。使えるモデルの一覧は、API の `/v1/models` で取得できます
- `llm-jp-3.1-8x13b-instruct4` は、試したところ system の指示（JSON の形）に従わず、普通の文章で答えました。06 で「モデルによって指示の効き方が違う」例として見せることもできます
