# 02 中をのぞく：AI とのやり取りを見る（15分）

01 でカードが作れた状態から始めます。この章では、カードを作るときにプログラムが AI に何を送り、何を受け取ったのかを「通信ののぞき窓」で見ます。そのうえで、API とは何かを説明します。

## 1. のぞき窓を開く

### やること

1. 「たこ焼き」でカードを1枚作ります（01 で作ったあとなら、そのままで大丈夫です）
2. カードのすぐ下にある「通信ののぞき窓（クリックで開く）」を押します

<!-- 画像: 閉じた状態ののぞき窓 -->

### 結果

のぞき窓が開き、上から順に次の内容が並びます。

| 見出し | 中身 |
|---|---|
| 送ったもの | 送り先の住所、ヘッダー、AI に送ったデータ |
| 1回目 | AI から返ってきたもの、チェック結果、使ったトークン数 |
| ぜんぶでかかった時間 | 頼んでから返事が来るまでの秒数 |

<!-- 画像: 開いた状態ののぞき窓 -->

## 2. 送ったものを読む

### やること

「送ったもの」の部分を、上から順に読みます。

### 結果

まず送り先として `POST https://api.ai.sakura.ad.jp/v1/chat/completions` が表示されています。その下の黒い枠には、次のようなデータが出ています。

```
{
  "Authorization": "Bearer 1a2b****",
  "Content-Type": "application/json"
}
```

もう1つの黒い枠が、AI に送ったデータの本体です。

```
{
  "model": "gpt-oss-120b",
  "messages": [
    { "role": "system", "content": "あなたは「なんでも図鑑」の編集者です。…" },
    { "role": "user", "content": "たこ焼き" }
  ],
  "temperature": 0.7,
  "max_tokens": 3000
}
```

### なにが起きたか

送ったデータの1つずつの意味は次のとおりです。

| 名前 | 意味 |
|---|---|
| `Authorization` | 自分を証明するキー。のぞき窓では、先頭4文字のあとを `****` で隠しています |
| `model` | どの AI に答えてもらうか |
| `messages` の `system` | AI への役割と指示。図鑑の編集者として、決まった形で答えるように頼んでいます |
| `messages` の `user` | 入力した言葉 |
| `temperature` | 答えのバラつき具合（04 で扱います） |
| `max_tokens` | 返事の長さの上限 |

`system` の中身は1行に詰まっていて読みにくいので、その下に「AI への指示（system）を読みやすくしたもの」として改行つきで出し直しています。読んでみてください。「次の形の JSON だけを返してください」という指示が入っています。

JSON（ジェイソン）は、データを `"名前": 値` の組で書く書き方です。人にもプログラムにも読みやすいので、プログラム同士のやり取りでよく使われます。

## 3. 返ってきたものを読む

### やること

「1回目」の部分を読みます。

### 結果

「返ってきたもの」の黒い枠に、AI の返事がそのまま出ています。

```
{
  "name": "たこ焼き",
  "category": "食べ物",
  "power": 70,
  "cuteness": 85,
  "description": "外はカリッと、内はとろ～な丸いおやつ。たこが入っていて、みんなで楽しく食べられるよ。"
}
```

その下には「チェック結果：OK」と、「使ったトークン数：入力 212 ／ 出力 493 ／ 合計 705」のような数字が出ています。

### なにが起きたか

AI は、指示どおり JSON の形で答えを返しました。カードに出ている値は、この返事から取り出したものです。

トークンは、AI が文章を数えるときの単位です。日本語では、だいたい1文字が1トークン前後です。出力のトークン数が返事の文字数よりずっと多いのは、このモデルが答えを書く前に「考える」分もトークンとして数えているためです。AI のサービスの多くは、このトークン数で利用量を数えます。

## API とは何か

ここまでで見たやり取りを並べ直すと、次のようになります。

- 決まった住所（`https://api.ai.sakura.ad.jp/v1/chat/completions`）に
- 決まった形のデータ（`model`、`messages` などを含む JSON）を送ると
- 決まった形のデータ（答えの入った JSON）が返ってくる

このような「プログラムから使うための窓口」を API といいます。窓口の使い方は、サービスを提供する側（ここではさくらインターネット）が説明書として公開しています。人が画面でボタンを押す代わりに、プログラムが決まった形でデータを送ることで、AI をアプリの部品として使えるようになります。

## なぜ自分のサーバーを間にはさむのか

このアプリのデータは、次の順に流れています。

```
[ブラウザ]  ──「たこ焼き」──▶  [自分のサーバー]  ──キー＋指示＋「たこ焼き」──▶  [さくらのAI Engine]
 public/app.js                   server.js                                         
            ◀──カードのデータ──                  ◀──────── AI の返事 ─────────
```

<!-- 画像: ブラウザ→サーバー→AI の経路の図 -->

ブラウザから直接 AI を呼ぶこともできそうに見えますが、そうするとキーをブラウザ側のプログラムに書くことになります。ブラウザで動くプログラムは、見ている人なら誰でも中身を読めるので、キーが丸見えになってしまいます。

そこで、キーは自分のサーバーの中だけに置き、ブラウザからは言葉だけを送るようにしています。のぞき窓のキーが `****` で隠れているのも、ブラウザにキーを渡さないためです。

## AI を呼んでいるプログラムを読む

最後に、実際に AI を呼んでいる部分を読みます。

### やること

エクスプローラーで `src` フォルダを開き、`ai.js` をクリックします。

### 結果

50行ほどのプログラムが表示されます。どの行にも、何をしているかのコメントがついています。

### なにが起きたか

`fetch(config.endpoint, { ... })` の部分が、AI の住所にデータを送っているところです。中を見ると、のぞき窓で見た `Authorization`、`Content-Type`、`model`、`messages` が書かれています。のぞき窓に出ていたのは、このプログラムが実際に送ったデータそのものです。

全部の行がわからなくても大丈夫です。「住所にデータを送り、返ってきたデータから `choices[0].message.content`（AI の返事の本文）を取り出している」という流れがつかめれば十分です。
